- **What it is:** the private conversation between the setter and the seller about ONE lead. Routes: `/api/marketing/chat/[leadId]` (GET, `?mark_read=0` while in the background), `…/messages` (POST), `…/read`, `…/upload-url` (signed upload into the lead's folder), `…/delivered`, `…/unread`, `…/conversations`, `…/messages/[id]` (PATCH, DELETE), `…/react`, `…/transcribe`.

A voice note is recorded as a flat MP4 in the browser before it is sent, so the stored attachment is marked `flat` (no repair route needed).
- **New messages arrive by a short refresh (4 s) while the window is open and on screen**, not by realtime: marketing logins cannot read the database tables directly. "Typing…" IS live (Supabase broadcast `tdm-lead-typing-<lead id>`, nothing stored, same as TD Talk). The board reads the leads again every 15 s while on screen, and right after any save inside a window (`FrameChangeNotifier`).

## The Inbox (built 2026-10-25, sandbox; dev job 9aec66fa)
- **What it is.** A small mail client for the team inside `/marketing/inbox`: address buttons (with unread numbers), search, Inbox/Sent/Drafts/Starred, thread view, Reply / Reply all / Forward / Archive / Delete (bin, not erased) / Mark unread / Star / Print / Copy link, New email with Cc/Bcc, rich editor, signature, attachments. It reads Gmail LIVE (no copy is stored here).
- **Which addresses exist.** ONLY Antonio adds them, in CRM > Marketing > Settings > "Inbox addresses" (`app/(dashboard)/marketing-leads/settings/inbox-addresses.tsx`; route `POST /api/marketing-admin/inbox-mailboxes`, strict admin). The setting `inbox_mailboxes` (`lib/marketing/settings-schema.ts`) is a list of `{address, people[], signature}`; fail-closed default `[]`. Adding runs the checks in `lib/marketing/inbox/admin.ts` + `mailboxes.ts`: must end `@tonydurante.us`, not a CRM mailbox (support@, antonio@…), not already added, and the system must be able to open it (one cheap Gmail read). Default visibility = the person it looks like (e.g. rocco@ → Rocco) — Antonio ticks more people.
- **The wall.** The Gmail key can open ANY company mailbox, so this list is the only thing between a Marketing user and support@. Every route goes through `requireInbox(address)` (`lib/marketing/inbox/access.ts`): permission `inbox` + `findOpenable` (admin → all listed; the people Antonio ticked; a matching login email is NOT enough, because a team owner can invite any address) → otherwise a generic 404 "Mailbox not found." CRM mailboxes are refused even for Antonio. A unit test scans every Marketing Inbox file and fails if it touches the CRM inbox code (`/api/inbox/`, `mailbox-access`, `email_index`, support@ …).
- **Sending.** The sender is always the mailbox (never the user's own login). `sendOrDraft` in `send.ts`; double-click guard `sendKey`. Attachments are uploaded straight to the private bucket `marketing-chat` under `<team>/inbox/<user>/…` by signed URL, read back only from the user's own folder, and deleted after the send. Attachments from Gmail are served as downloads only (octet-stream + `nosniff` + CSP sandbox, inline only for raster images); email HTML is sanitized and shown in a sandboxed iframe.
- **Driver.** `lib/marketing/inbox/driver.ts` is the only door to Gmail (`MailDriver`). A fake in-memory driver exists for local tests only: it needs `MARKETING_FAKE_MAIL=1` AND a local Supabase URL AND not production/Vercel (`fakeMailAllowed`).
- **Drafts and uploads (2026-10-26).** "Edit draft" brings the draft back as saved (its own To/Cc/Bcc, formatting, and the same conversation when it answers an email); the draft's text already holds the signature and the quote, so the send carries `complete: true` and the server adds neither again. Uploaded attachments are deleted when removed from the email, when the email is closed or left without sending (`DELETE /api/marketing/inbox/attachments`, own folder only), and anything older than a day is swept at the next upload (`sweepStaleStaged`). Leaving a half-written email (another folder/address/email) asks first. The real driver saves the new draft BEFORE deleting the old one and looks for the draft id through up to 500 drafts.
- **Drafts: unsent drafts are flagged (`MailMessage.draft`) and never quoted or answered; Edit draft uses the draft's own message even when newer emails arrived after it; Reply uses the newest non-draft email. KNOWN LIMIT: an edited reply draft shows its quoted original and signature as plain paragraphs (the editor's allow-list has no blockquote), and a draft written in Gmail's own screen loses tables/images.** Discard asks first when something is typed or a saved draft exists.
- **Known limits (told to Antonio).** Forward is text only (original attachments not forwarded); drafts do not keep attachments (they are thrown away with the box); no audit-log entry per send; real Gmail behaviour is covered by unit-parsing only, not a live run on sandbox; the unread number polls every 60 s per open tab.

## Gotchas
- The shared apply script `scripts/apply-migration.js` forces SSL and fails on the private local stack ("server does not support SSL"). Apply with `docker exec -i <db container> psql -U postgres -d postgres < file.sql`.
- A rate change is a NEW term row with a later effective date. A sale takes a snapshot of the term when its payment link is created, so old sales never change.
- Do not add a hardcoded stage name, reason, percentage or switch anywhere: add a key to `settings-schema.ts` instead.
