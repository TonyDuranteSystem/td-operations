## What it is
The client portal (portal.tonydurante.us) as an iPhone app. A thin native shell shows the portal's own pages inside the app (`TDSocial/`-style "app mode"), with a native bottom bar, a Menu, phone alerts and one sign-in. It ships as **version 2.0 of the existing App Store record "MyLLC Manager"** (bundle `com.tonydurante.myllcmanager`, Apple ID 6749905082), public, for **clients and the team members they added** (no partners). Paying Tony Durante invoices works inside the app, with a server switch that hides Pay if Apple objects.

## The approved design (Antonio, 8 Nov 2026)
- **Overview** = the portal's real Overview page. **My Company is not in the app.** No in-app account deletion (staff do it from the CRM). The voice button is the record button built in another session.
- **Invoices** = the client's OWN invoicing (portal "Customers & Invoices": Setup, Customers, Sales, Vendors, Expenses), with a not-set-up card (bank account or payment link REQUIRED, first customer with an email REQUIRED, logo optional; no "Not now"). **TD Billing** is its own item and its own screen (`/portal/invoices?tab=billing` in the app; shown only once TD has sent an invoice, carries the unpaid count).
- **Bottom bar:** Chat is the only fixed tab and the client picks four. **The Menu is a round button at the top right of every screen**; its red number counts waiting items that are not in the bar. A new client's standard set: Overview, Chat, Documents, Invoices, and a fifth = TD Billing if the client has an invoice from Tony Durante, otherwise Sign Documents. The choice is saved with the login (candidate store: `portal_user_preferences`, whose writer accepts only `tour.*` keys today).
- **Chat:** one "Topic" button next to the title (opens a short list, unread topics red and first, "Create a new topic"); no Journey Log; **Chat opens on the topic of the newest unread answer** (the website opens General first and, with several unread topics, the one with the most unread — the app uses Antonio's rule instead); the button's red number counts unread answers in the other topics.
- **Paying** = the portal's real "Pay Invoice" pop-up (card + the card fee on what is still owed, bank transfer with the required payment reference). Inside the app "Pay Now" leaves in the app's own window and the card page returns the client to the TD Billing screen (Step 3 bug-hunter fixes). **Not tried yet on a real phone.**

## Rules and gotchas
0. The app's 44 px minimum for icon-only buttons and text buttons (`app/globals.css`) inflates anything small a page draws: before adding a row of small icons to an app screen, check it on a phone-width page in app mode. `.app-compact-taps` exists for message lists but the client Chat uses tap-for-actions instead.
1. App mode is a layout hint, never a security switch (see `social-app.md`). Every app-only style stays behind the app marker; `tests/unit/app-mode-css.test.ts` guards the stylesheet.
2. `/api/portal/` is open to client logins by the client API allow-list but also holds staff routes: every new route there needs its own client-or-team-member check.
3. TD Social's `lib/app/environment.ts` accepts ONE bundle id per server and its doors refuse clients. The client app needs its own accepted bundle id and its own door.
4. A TestFlight build stops working 90 days after upload. A change to the app itself needs a new build and Apple's review; web changes reach the app at once.
5. Step 1 is live (it changes nothing anyone sees). Step 2's doors go live on production the moment it merges but answer 503 until `client_app_enabled` is set to `true`; no database file is needed (the bar is one more key in the existing `portal_user_preferences` row, the phones use the existing `social_app_devices` table). Switching on was the LAST step and was done on Antonio's explicit word (10 Nov 2026).
6. Do not build a RegExp from a template string with a constant (R115); the production build is not the dev server.
7. Release plan (Antonio, 10 Nov 2026): set up everything in Apple and test it privately first; the PUBLIC launch is planned for January 2027. "MyLLC Manager" (Apple ID 6749905082) is live on the App Store as version 1.3 ("Ready for Distribution"), so 2.0 is an update of that live record: nothing reaches today's users until 2.0 is released. App Store Connect's version page (seen 10 Nov 2026) offers "Manually release this version" and "Automatically release this version after App Review, no earlier than <date>", so 2.0 can be approved and still held back; testing before that is TestFlight (a build stops working 90 days after upload, rule 4). `client_app_enabled` was turned ON in production by Antonio's word on 10 Nov 2026 (the app was uploaded to TestFlight the same day); do not submit 2.0 for review until Antonio says.
