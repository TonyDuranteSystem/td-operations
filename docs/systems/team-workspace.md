## What it is
The internal team chat, rebuilt from a single "Team General" room into a full workspace: **named channels**, **direct messages**, **client discussions**, and a **general** room — all staff-only, never client-visible. Reactions, edit-with-history, pins, message search, @mentions with targeted push, colored rich cards, and an **@claude** AI-worker trigger. Backed by the same `internal_threads` / `internal_messages` tables that already powered the old team chat + `portal_team_send` (so nothing pre-existing broke — the change is additive).

Two UI surfaces read these tables and both keep working:
- `/team-chat` — the new **Team Workspace** page (this subsystem).
- CRM **Portal Chats → Team tab** (`app/(dashboard)/portal-chats/page.tsx`, `view=internal`) — the legacy per-client internal-thread view, untouched. `portal_team_send` still writes here.

## Data model
`internal_threads` — one row per channel / DM / discussion / general room. `thread_type` ∈ `general | channel | discussion | dm` (CHECK). Channel cols: `channel_name`, `channel_slug` (partial-unique), `description`, `color`. DM col: `dm_key` = sorted `"idA:idB"` (partial-unique → one thread per pair). `resolved_at` (discussions), `archived_at`, `last_activity_at` (sidebar sort). Legacy cols retained: `account_id`, `contact_id`, `source_message_id`, `title`, `created_by`.

`internal_messages` — `reactions` jsonb `[]`, `edited_at` + `original_message` (edit history), `pinned_at`/`pinned_by`, `mentions` jsonb (matched handles), `card` jsonb (rich card). Legacy retained: `attachments`, `reply_to_id`, `deleted_at`/`deleted_by` (R100 soft-delete), `read_at`/`seen_at` (legacy — superseded for unread by the reads table).

`internal_thread_reads` — **per-user read pointer** (`thread_id`, `user_id`, `last_read_at`, PK both). This is the unread model. Staff-only RLS matching the sibling tables (prod has RLS on; sandbox off — a green sandbox test does NOT prove RLS).

Realtime publication members: `internal_messages` (pre-existing) + `internal_threads` + `internal_thread_reads` (added Phase 1).

## Read-side RPCs (avoid N+1)
- `get_team_threads(p_user_id)` → every visible thread + **per-user `unread_count`** (`msgs where created_at > COALESCE(last_read_at,'-infinity') and sender_id<>user and deleted_at is null`) + last-message preview. DMs filtered to those whose `dm_key` contains the user id; channels/general/discussions visible to all staff. Excludes `archived_at`.
- `search_team_messages(p_user_id, p_query)` → ILIKE search across visible messages (same DM rule), cap 50.
- `toggle_internal_message_reaction(msg, emoji, reactor_id, reactor_name)` → atomic add/remove keyed on (emoji, reactor). Mirror of `toggle_message_reaction` (that one is bound to `portal_messages` — do NOT reuse it here).

## New conversation (native, Slack-independent — the Client-Threads modal, reimagined)
The "New conversation" entry on the **Client Discussions** sidebar header opens a modal (mirrors the Slack Client-Threads modal) — pick a **client** (account/contact/lead search), an optional **topic** (from the `topic_templates` catalog or free-typed), and optionally a **channel** to also drop a card into. - `GET /api/team/client-search?q=` — accounts (`company_name`) + contacts (`full_name`) + leads (`full_name`), staff-only, returns `{value:"<kind>:<uuid>", label, sublabel, kind}` (mirrors the Slack modal's 3-table search). Topics come from the existing `GET /api/portal/chat/topic-templates`.

## Share to team chat — from Inbox & Portal Chats (built 2026-07-08, LIVE ON PROD 2026-07-09 commit `1a02c4ef`)
Antonio's request: from a specific email in the CRM **Inbox**, or a specific client message in **Portal Chats**, share it into the team chat as a **DM** — either to a chosen teammate (to discuss) or to a configured **support person** (a support intake queue). A multi-select share to Support posts **one message per item** (never merged). Each shared post carries the sharer's **notes** (message body) + a **card** linking back to the source.
- **One endpoint** — `POST /api/team/share` (`app/api/team/share/route.ts`). Body `{ target: 'support' | { user_id }, note?, items[] }`. Resolves the recipient (support person via `getSupportPersonUserId()`, or the passed teammate — both validated against `listTeamMembers`), find-or-creates the DM, inserts **one `internal_messages` row per item** (note as `message`, item as `card`), bumps `last_activity_at`, advances the sender's read pointer. **Notifies ONLY the recipient** via `sendPushToAdminUsers([recipientId])` — deliberately NOT the normal send route, which broadcasts DM/thread activity to the whole staff (`sendPushToAdminExcluding`); reusing it would ping everyone on every share. Self-share (recipient === sender) skips the push.
- **DM find-or-create is shared** — `lib/team/dm.ts::findOrCreateDm(a, b)` (deduped by `dm_key`, race-safe). Both `POST /api/team/dms` and the share route use it — never hand-roll a DM insert.
- **Full source text in the body** — each shared message's body = the sharer's note + the item's ENTIRE text (`composeShareMessage(note, body, cap=SHARE_BODY_CAP)`, capped at 4000 chars with a truncation marker). Inbox single-share fetches `/api/inbox/messages/<id>` and strips the email HTML to plain text (`stripEmailHtml` in `inbox-shell.tsx`); portal passes `msg.message`; bulk email share stays snippet-only (no per-item fetch). The card remains the compact titled link.
- **Card building is pure + unit-tested** — `lib/team/share.ts::buildShareCards(rawItems, max=25)` returns `{ cards, error }`: defaults `kind` to `client_message`, requires a **relative** in-app `url` (rejects external links), runs each through `validateTeamCard`, fails closed on the first bad item. Tests in `tests/unit/team-share.test.ts`. (Note: a discriminated-union `{ok}` result shape tripped an anomalous TS narrowing failure only in this project's compile context — the flat `{cards,error}` shape is the deliberate workaround.)
- **Support person is configurable** — `support_person_user_id` app-setting (`lib/settings.ts::getSupportPersonUserId()`) stores the **actual auth user UUID** (no runtime name-resolution — brittle). Seeded to the support@ team account in both envs: **prod** `deb9becc-01d5-4d76-a29a-195a6d5b2857` (name "support"), **sandbox** `55ac2225-42ad-4215-b79b-9d610fefc6c5` (name "Luca") — same operational account, different label. If unset, the endpoint returns a 409 "no support person configured" rather than guessing. Change it with a single app-setting update.
- **Shared dialog** — `components/team/share-to-team-dialog.tsx` (`ShareToTeamDialog`): target toggle (Support | teammate picker from `GET /api/team/threads` `members`, self excluded), notes box, item preview, success toast with an "Open" link to `/team-chat?thread=`. Optional `onShared` callback (Inbox uses it to clear a bulk selection). Reused by BOTH surfaces — do not fork.
- **Inbox surface** (`components/inbox/inbox-shell.tsx`): a per-thread "Share to team chat" header button (email → `kind:'link'` card, subject as title, sender + snippet as subtitle) + a **bulk "Share to team"** button in the selection bar (resolves `selectedIds` → conversation objects from the `inbox-conversations` react-query cache). Card links back via a **new inbox deep-link**: `/inbox?thread=gmail:<id>&mailbox=support|antonio`, hydrated on mount from `window.location` (the inbox had no addressable single-email URL before — added here; it fetches `/api/inbox/messages/...` for the header subject/sender).
- **Portal Chats surface** (`app/(dashboard)/portal-chats/page.tsx`): a "Share to team chat" item in the per-message kebab (next to "Discuss with Team"). Card = `kind:'client_message'`, title = client/account name, subtitle = message text, back-link `/portal-chats?account=<id>&message=<id>` (or `?contact=`). Single-message only for v1 (that page has no multi-select; deferred).

## Business rules / invariants
- **Staff-only, never client-visible.** All routes gate on `isDashboardUser`; RLS is staff-only.
- **Unread is per-user** via `internal_thread_reads`. Do NOT reintroduce logic based on the single `read_at` column for unread (it made counts always 0 — the pre-Phase-1 bug, because sends stamped `read_at=now()`).
- **@claude trigger scope**: an explicit mention anywhere, PLUS plain text messages in a `discussion` where Claude has already participated (invitation gate, 2026-07-08).
