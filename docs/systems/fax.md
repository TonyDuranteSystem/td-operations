## What it is
A staff tool to send a document by fax via **Faxage** (faxage.com HTTPS API). Reached from the **Tools hub** (`/tools` → "Fax" tile, which links to both **Send Fax** and **Fax History**) at **`/tools/fax`**, and from the **"Send Fax to IRS"** button (`fax_irs` component) on three flow stages — Tax Return **"Signed"**, ITIN **"Submitted to IRS"**, and Company Formation **"SS-4 Signed"** (the button's wording adapts to the flow's service type). Sent faxes are listed at **`/tools/fax/history`** with on-demand live delivery status and a downloadable receipt (transmittal page).

## How it works
- **UI** `app/(dashboard)/tools/fax/page.tsx` (server, fetches recent Drive-backed documents + the configured IRS number) + `fax-form.tsx` (client): recipient fax number, recipient name (optional), optional **Reason** (free-text "why this fax was sent" — shown in Fax History), **document source toggle — upload a file (PDF/image, ≤10 MB) OR pick a recent document** from a dropdown, optional cover message. Upload path reads the file as base64 client-side; document path sends the `document_id`. Pre-fills from query params (`to`, `message`, `faxno`, `reason`); `to=IRS` pre-fills the configured IRS fax number. **[SUPERSEDED 2026-10-20: upload limit is now 3 MB (request-size limit) and Send Fax on an uploaded file opens the required save-where window first — see the top of this file.]**
- **API** `app/api/tools/fax/send/route.ts` (staff-only via `isDashboardUser` → 403): accepts JSON with either `file_base64`+`file_name` (upload) or `document_id` (a `documents` row → downloaded from Drive via `downloadFileBinary`, base64-encoded server-side). Sends via `lib/fax/faxage.ts::sendFax` (the chosen save place is checked BEFORE; the `action_log` row is written right AFTER Faxage accepts and completed after the filing — SUPERSEDED detail: the file-name auto-filing no longer exists) and writes an `action_log` row (`action_type='fax_sent'`, with `faxno`/`recip_name`/`reason`/`file_name`/`job_id`/`source` in `details` — this row is the source of the Fax History page). `reason` is an optional free-text "why this fax was sent" (e.g. "Tax Return filing for Profit Harbor LLC"); JSONB-additive, no migration. `GET` returns the configured IRS number (no secrets) for the UI. **[SUPERSEDED 2026-10-20: the route also takes `save_choice` + `send_id`, checks the place before sending, writes the history row right after Faxage accepts, never trusts an upload's `account_id`, and keeps the internal copy only where the top of this file says.]**
- **Library** `lib/fax/faxage.ts` (pure + unit-tested, `tests/unit/faxage.test.ts`): `normalizeFaxNo`/`isValidFaxNo` (digits-only, 10–15), `stripBase64Prefix`, `buildFaxageParams` (posts `operation=sendfax`, `username`, `company`, `password`, `faxno`, `recipname`, **indexed** `faxfilenames[0]`/`faxfiledata[0]`), `parseFaxageResponse` (SUPERSEDED 2026-10-20 — returns an `outcome`: **refused** only for Faxage's own `ERRnn` token at the start of a short plain body; **accepted** only for a short plain 2xx body with a job id (labelled, or just the 8–12-digit number, e.g. 1122910119); everything else — gateway pages, "Error 502", empty/HTML bodies, error words inside an answer — is **unknown** and keeps the claim), `sendFax` (injectable fetch). **Status/receipt helpers:** `buildStatusParams`/`parseStatusResponse`/`getFaxStatus` (`operation=status`; posts a FIXED set of optional flags — `pagecount`/`csid`/`showlogin`/`xmitpages`/`showtries` all `=1` — so the appended tab-separated columns land in deterministic positions; `normalizeStatus` maps Faxage `shortstatus` success/pending/failure → delivered/pending/failed; **ERR06 = "no jobs" is returned as an empty, non-error result**); `buildDltransParams`/`interpretTransmittalBytes`/`getFaxTransmittal` (`operation=dltrans`, `jobtz` default `4`=Eastern; success body is a PDF detected by the `%PDF` magic bytes, otherwise the body is treated as an `ERRxx` message).
- **History UI** `app/(dashboard)/tools/fax/history/page.tsx` (server, queries `action_log` for `fax_sent` — newest 200 — AND, separately, `fax_claim` (unconfirmed sends, newest 100, shown FIRST so they can never fall out of view); SUPERSEDED 2026-10-20: it no longer reads only `fax_sent`) + `history-table.tsx` (client). Columns: date, recipient (name + number), document, reason, status, job id, receipt. The **document cell links to `/api/documents/[id]/preview`** when sent from a stored document (`record_id` present + `source='document'`); upload-sourced rows show the filename as plain text (no persisted file). **History rows come from `action_log` and render without any Faxage call** (so the list works even if Faxage creds are wrong); **live delivery status is on-demand** via the per-row "Check status" button. **[SUPERSEDED 2026-10-20: an upload row links "View Document" only when a copy exists; otherwise the row carries a plain note (`lib/fax/history-note.ts`): My files / personal paper / the copy was not saved.]**

## Config
- **Env (server-only):** `FAXAGE_USERNAME`, `FAXAGE_PASSWORD`, `FAXAGE_COMPANY` (Faxage account "company"; defaults to username if unset), `FAXAGE_IRS_NUMBER` (default `8552151627` from `DEFAULT_IRS_FAX_NUMBER`). In `.env.local` (gitignored) for local/sandbox; must also be set in the Vercel project env for deployed routes.
- Credentials are NEVER sent from the client or committed to git.

## Gotchas / unverified
- **Faxage operation vocabulary — sent vs received (verified from the official Faxage HTTPS API PDF, 2026-06-15):** for **sent** faxes the operations are `sendfax` / `status` / `dlstatus` / `dltrans` / `stopfax` / `resend` / `clear`. The `listfax` / `getfax` / `delfax` operations are for **received (incoming)** faxes and must NOT be used for sent-fax history or receipts. That is why the history page is built from `action_log` (send-time record) + the `status` operation (live delivery), and the receipt is `dltrans` (the transmittal PDF) — NOT `listfax`/`getfax`.
- **Live status / receipt depend on working Faxage creds.** The history *list* renders from `action_log` regardless, but **Check status** (`status`) and **Receipt** (`dltrans`) make live Faxage calls and will fail with the credentials error below until correct `FAXAGE_*` creds are set. `dltrans` also returns `ERR28` until a job has finished sending (the transmittal page doesn't exist while pending).
- **`status` optional-flag ordering:** Faxage appends optional columns (`pagecount`,`csid`,`login`,`xmitpages`,`number-of-tries`) only for the flags posted, in that fixed order. `buildStatusParams` posts ALL five so `parseStatusResponse` can read fields by fixed index. If you change which flags are posted, update the parser's indices.
- **Auth (2026-06-15): Faxage returns `ERR02: Login incorrect`** for `username=password=company=support@tonydurante.us` (verified live via read-only `operation=listfax` — fails in every combination tried, with and without `company`). The endpoint + request shaping are correct (Faxage parses far enough to reject the LOGIN). Faxage authenticates with the account's **Company** (account identifier — usually NOT the email) + **Username** + **Password**; the email-as-everything credentials are wrong. **The fax cannot send until the correct Faxage Company/Username/Password are set** in `FAXAGE_*`. The route now logs the full raw response to `console.error` and returns a credentials-specific error on `ERR02`/"login incorrect".

- **The Faxage `sendfax` success format is VERIFIED from production data (2026-10-20):** every stored `faxage_response` matches `^JOBID: [0-9]{8,12}$` (e.g. `JOBID: 1122910119`). `parseFaxageResponse` accepts exactly that kind of plain answer (and a bare 8–12-digit number); the exact real string has its own unit test. Refusals are Faxage's `ERRnn` token (e.g. `ERR02: Login incorrect`); anything else is an unknown outcome (see the Library bullet). SUPERSEDED: the old "heuristic / UNVERIFIED" wording.
- **Cover message is recorded in `action_log` but NOT transmitted** — the documented Faxage fields have no cover-page param we can rely on. Wire it once confirmed from Faxage's docs.
- **Sandbox `downloadFileBinary` returns a placeholder PDF** (it short-circuits when `SANDBOX_MODE=1`), so faxing a *selected document* in sandbox sends a mock PDF, not the real file. Upload path uses the real uploaded bytes.
- **Faxage is a real external service with no sandbox** — any send goes out for real. Test deliberately with a safe number.
- E-Sign tile on the Tools hub is a **placeholder** ("Coming soon") — non-navigating.

## How to verify current state
- Open `/tools` → "Fax" tile present with **Send Fax** + **Fax History** links; `/tools/fax` renders the form with upload / recent-document toggle and a **Fax History** header link.
- Open `/tools/fax/history` → table of sent faxes from `action_log` (renders even with bad Faxage creds). Each row with a job id shows **Check status** (live `status` call) and **Receipt** (opens `/api/tools/fax/receipt/<jobId>` PDF).
- After sending, the success panel shows **Send another fax** + **View Fax History**.
- Open a Tax Return SD at "Signed" → the "Send Fax to IRS" card appears next to File-with-IRS; clicking it opens `/tools/fax` with the IRS number pre-filled.
- `npm run test:unit` covers `lib/fax/faxage.ts` (send, status, dltrans helpers).
- A real send + live status/receipt require correct `FAXAGE_*` env set in the target environment.
