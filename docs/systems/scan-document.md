# Scan document (the chat attach tool)
_Last verified against code: 2026-11-10 — Claude (dev job `26947ea3`, SANDBOX — Antonio ships; NO migration; web only, no new iPhone build). Antonio: "I want the option to scan document in attachment tool for TD Talk, WA, Marketing, Portal chats", then "Yes, live camera" and "Approve, build it" on the mockup (https://claude.ai/artifact/BHgYMr7qZbecgws6jYtaTQ). **Built in the sandbox and browser-tested with a simulated camera; NOT tested on a real iPhone, in the TD Social app, or on production.**_

## What it is
The paperclip in a chat box now opens a small menu: **Scan document** (camera → one PDF) or **Photo or file** (exactly what the paperclip did before). Scan document is a full-screen scanner: a live camera that finds the page by itself and takes the picture when the outline holds still, then a screen to check each page (straightened, three looks, drag the corners if the outline was off), then all the pages in one list (reorder, remove, add, name the file), then **Attach PDF · N pages**. The PDF is handed to the chat's normal attach path as if the person had picked a file, so every existing size / type check still applies. **Nothing leaves the phone until the person presses Send** (the scanner has no network call; a test guards that).

## Business rules (Antonio's decisions, 2026-11-10)
- **Method:** live camera with automatic page detection (his "Yes, live camera"); manual corner handles are the fallback. Apple's native scanner (VisionKit) was NOT chosen: it needs a new TD Social build + Apple review — a possible later upgrade.
- **Where:** TD Talk, the Marketing lead chat and team chat (they share TD Talk's message box), WhatsApp (computer paperclip + the phone "＋" sheet), staff Portal Chats (computer paperclip + the phone sheet), and **Inbox email** (added 2026-11-10 at Antonio's request: the **Attach** button of the reply / forward composer `components/inbox/compose-reply.tsx` — which the Portal Chats email panel also embeds — and the **Attach files** button of the New Email dialog `components/inbox/compose-dialog.tsx`, which the Share-file window and the captures panel also open; a scan joins the attachments through `useEmailAttachments().add`, the same staging and checks as a picked file). **NOT the client's own portal chat** (staff screens only until he says otherwise). NOT the Marketing mailbox's own "Attach" button (`components/marketing/inbox/composer.tsx`), NOT the "Add a file" button on the Inbox worker's confirm-before-send card (`components/inbox/confirm-attachments.tsx`) and NOT the Portal Chats internal Team composer.
- **Defaults I proposed and he approved with the mockup:** at most **20 pages** per scan; the first look is **Colour** (right for passports / IDs; **Document** is one tap away); **auto-take on** with the round shutter always available and an "Auto: off" switch.
- **IDs and passports are fine to scan and send on WhatsApp:** the old "don't send ID or tax documents over WhatsApp" reminder was removed the same day (see `messaging.md`, 2026-11-10).

## How it's built
- **Menu:** `components/scan/attach-choice-menu.tsx` (opens upwards by default, or downwards with `placement="below"` — the New Email dialog's Files row is near the top of the dialog — inside a `relative` wrapper; "outside" means outside the paperclip's wrapper, so the paperclip itself toggles). Both choices run straight from the tap, so the phone's file picker still opens. The phone "＋" sheet (`PhonePlusSheet` in `components/portal-chats/app-phone-chrome.tsx`) gets an optional `onScan` row; with it the file row reads "Photo or file".
- **Surfaces:** `components/talk/talk-composer.tsx` (`pick` now takes any list of files), `components/inbox/whatsapp-thread.tsx` (a scan goes through `uploadAndStageFile`), `app/(dashboard)/portal-chats/page.tsx` (a scan goes through `handleAdminFileSelect`).
- **Scanner:** `components/scan/document-scanner.tsx` (the whole flow, rendered in a portal on `document.body`, full screen) with `scan-camera.tsx`, `scan-adjust.tsx`, `scan-pages.tsx`, `scan-types.ts`. The camera screen is mounted only while it is on screen, so the camera is released on every other screen.
- **Pure logic (tested, no browser):** `lib/scan/geometry.ts` (corner order, sizes, perspective map and the straightening warp), `detect-page.ts` (the page finder + `refineQuad`), `steady.ts` (hold-steady rule), `enhance.ts` (the three looks), `session.ts` (page limit, file name, reorder), `pdf.ts` (pdf-lib, loaded only when "Attach PDF" is pressed). Browser-only glue: `lib/scan/browser.ts` (camera, canvas, JPEG).
- **Page finder** (`detectPage`, 10-50 ms on a 160-pixel-wide picture in the tests, run ~6 times a second): edge shapes at two strengths + the biggest bright / dark patch at three shade cut-offs → convex outline → four corners → accepted only when the outline lies on real edges **measured above chance** (a noisy table has edges everywhere), covers 12-97 % of the picture, has sane angles and does not have 3 corners pinned to the picture edge. `MIN_SCORE` 0.75: real pages scored 0.9+ in the tests, noise ~0.5. **`refineQuad` then re-measures every side on a ~1000-pixel picture** (strongest brightness step along many short lines, least-squares line, strays dropped, corners = where neighbouring lines cross) — without it the corners sat 8-12 px outside the paper and a dark rim showed.
- **Hold steady:** `createSteadyTracker` — 7 looks in a row with corners within 2 % of the diagonal → auto-take; the ring around the shutter fills while it waits.
- **Looks:** `colour` (one brightness stretch on all channels, colours kept), `grey`, `document` (paper brightness estimated from block maxima, divided out, smooth step → clean white paper, dark writing). Previews are made at 900 px; the PDF at 2000 px (JPEG 0.85), one page at a time with a progress count.
- **No camera / permission refused:** a card with **Take a photo** (`capture="environment"`) and **Choose a photo** (several allowed → straight to the pages list); each photo goes through the same page finder.
- **Italian:** the scanner strings go through `useTalkI18n().t`; TD Talk and the CRM have no provider (English), the Marketing chat translates from `lib/marketing/i18n-it.ts` (48 new entries; a test checks every `t('…')` in `components/scan/` has one with the same `{slots}`).

## Gotchas, invariants & past bugs
- **Corners are in the ORIGINAL photo's pixels** (kept as a JPEG ≤ 2400 px); the preview is re-rendered from it on every look / corner change, never from the previous preview.
- **Hold-and-drag reorder** (`scan-pages.tsx`): a 280 ms hold starts the drag and a window `touchmove` blocker stops the page scrolling while a page is carried; a move before the hold ends counts as a scroll. Tap opens the page. **Never tried with a real finger** — pointer events were simulated.
- **Pointer capture on the corner handles is in a try/catch** (a simulated pointer id threw); real touches are fine.
- **Dev mode starts the camera twice** (React Strict Mode); each start stops its own stream.
- **A new camera stream is opened each time the camera screen returns** (after a page is checked) and released when it leaves, so the camera is only on while that screen is. Not measured on a phone: how long the restart takes.
- The page finder was **tuned on drawn pictures** (perspective, uneven light, texture, noise, a smaller bright object nearby), not on real photos. A real table / hand / shadow may find the page worse; the corner handles are the safety net.
- A scan is hard-capped at 20 pages and 5 files per message still applies in the chat box (TD Talk `CHAT_ATTACHMENT_MAX_COUNT`, Portal Chats `MAX_ADMIN_ATTACHMENTS`).
