_Last verified against code: 2026-10-12 (CRM Storage archive under Business › BofA; partner + recipients + email delivery + tracking list; ITIN in the person section; Forms page) — earlier 2026-10-09 (after the 4-reviewer council pass) — Claude (dev job 11d484a4). ## What it is
A one-time link that a client (ours, or an external one such as a Max Scale client) fills out to apply for a US business bank account through a third-party intermediary (Irshad Ahangar / Open Shift LLC). The client types their details and a plain description of the business, and uploads passport, proof of address, business registration, EIN letter, ITIN letter and lease. **Everything is archived with us in CRM Storage (Business › BofA).** The only outbound email is the one to the addresses staff typed when they made the link, plus an internal ping to staff. The $2,500 client payment, a status-only shared sheet and any CRM/portal screens are deliberately NOT built (Antonio: "when the first account is opened and works we will build everything else").

## Business rules
- **One-time link.** Loading the page only READS the link's state. The visitor must press **Start application** (a POST) to claim it; the browser that does becomes its only owner (a secret cookie, 30 days; only the SHA-256 hash is stored). The same browser can refresh or return until it submits. Any other browser sees "already used". A submitted or revoked link is dead for everyone, including the opener. Staff can **Reset** an opened-but-unsubmitted link (client switched browser / cleared cookies): it goes back to "not opened" and the earlier uploads are deleted. **Revoke** also deletes the uploads.
- **Link scanners / preview bots.** Because loading the page never claims, a mail scanner or chat app that merely opens the URL cannot burn it (council finding). A real browser that presses Start can.
- **No CRM account needed.** Clients can be external; the row is keyed by token + a staff-chosen label only.
- **Documents:** PDF or photo (a missing browser type falls back to the file extension, e.g. iPhone .heic), 10 MB each, ONE per box (the server rejects two in one box). The bucket itself only accepts those types. Required: passport, proof of address, business registration, EIN letter, ITIN letter, lease. Optional: anything else.
- **The ITIN is the PERSON's, so it sits in the "About you" section next to citizenship (not in the company section)** — Antonio, 2026-10-12. The company section holds name, EIN, state of formation, address, website.
- **Addresses are always five fields** (street, city, region/province, zip code, country) — home and company.
- **Placeholders** in the form are invented neutral examples (Antonio: no Italy, none of his own data).
- **Decisions (Antonio):** consent wording / retention rule from the 2026-10-09 council were REJECTED by him ("bullshit") and verifying the intermediary is "not your business" — do not raise them again; the ITIN letter and the lease stay REQUIRED; the submitted form is emailed to addresses typed when the link is made (no separate release button); submissions are archived in CRM Storage under Business › BofA (2026-10-12).

## Archive in CRM Storage (2026-10-12, Antonio: "every application must be saved in storage, under Business, BofA")
- **Where:** `Business › BofA › <partner> › <date applicant - company (request id)> ›` the six documents (named after their box, e.g. "Passport photo page.pdf") plus **"Application answers.pdf"** (a PDF of the answers; it names the partner — internal only). The Business area is the firm's own: staff only, never shown to a client, no CRM `documents` row. Passport / proof of address / ITIN letter carry NO document type there (a personal type is refused for a non-person owner).
- **How:** after a submit stores the answers, `lib/bofa-intake/archive.ts::archiveSubmission` calls `ensureArea("business")`, finds the Business top folder, `store_ensure_folder_path(owner, root, ['BofA', partner, applicant], null)`, and saves each file through the ONE writer `saveBytesToStore` with caller key `bofa:<request id>:<slot>` (a retry never duplicates). It never needs a login (actor null).
- **Temporary copies:** the applicant's browser still uploads to the intake's own private bucket (`bofa-intake-uploads`; a public visitor cannot write to CRM Storage). Only when EVERYTHING saved are those temporary objects removed; the row's `files` entries then carry `store_file_id` and `temp_removed`. `lib/bofa-intake/files.ts` reads a file from whichever side it is on (email delivery, staff download). On any failure nothing is removed, the reason goes to `store_error`, the client's submission is NOT failed, and the list shows "Not saved yet: <reason>" with a **Save to Storage** button (`PATCH {action:"archive"}`).
- **Limits are ours:** CRM Storage has no size or type limit, so the 10 MB / PDF-or-photo rules are enforced by the intake before the copy.
- **Stored versions are permanent** (a database trigger blocks deleting them) — test only in the sandbox.
- Migration `scripts/migrations/20261012-1800-bofa-intake-storage-archive.sql` adds `store_owner_id`, `store_folder_id`, `store_archived_at`, `store_error`.
- The Business owner id differs between sandbox and production: always look it up (`ensureArea`), never hard-code it. The local isolated test database has NO store tables, so the archive can only be proven on the shared sandbox.

## Partner, recipients and the tracking list (2026-10-12, Antonio)
- **Making a link** (Forms page) asks for a **partner name** (required, e.g. Max Scale) and optional **"send the submitted form to" emails** (up to 5, comma-separated). There is no free-text label any more: `label` is just a copy of the partner name. The CLIENT the partner shares the link with is NOT typed — the list shows their name and company once the form is submitted (read from the answers).
- **Emailing the finished form:** on submit the app stores everything FIRST, then emails the answers + documents to those addresses (`lib/bofa-intake/deliver.ts`, R037 shape: atomic claim `email_status null -> sending`, send, then `sent` / `failed` + `email_error`). Documents are attached when the total is 18 MB or less, otherwise the email carries 7-day download links. A failed send never fails the client's submission; staff see "Not sent: <reason>" and a **Resend email** button (and **Email again** after a success, with a confirm). A send that died mid-way (stuck on `sending`) can be taken over by the button after 5 minutes. The email NEVER names the partner or any TD address/link — the recipient sees the application only.
- **The list** (`/bofa-intake`, "Links and submissions"): partner, shared-with client (+ company), status, created / opened / submitted, emailed-to + sent time or error, and per-row View answers and documents, Copy link (until submitted), Email again / Resend, Reset, Revoke.
- Migration `scripts/migrations/20261012-1200-bofa-intake-partner-recipients.sql` adds `partner_name`, `recipients[]`, `email_status`, `email_sent_at`, `email_error` (additive; sandbox-applied, not on production).

## The "Forms" page (CRM side menu, admin only)
Added 2026-10-12 at Antonio's request: a **Forms** entry in the left menu (right under Storage) opens `/forms`, the home for every STANDALONE form (not tied to a client account). Each form is a card with **View form** (the exact form the client sees, with nothing saved or sent — `/forms/bank-application/preview`), **Links and submissions** (`/bofa-intake`), and **Create and copy link** (names a new one-time link and puts it on the clipboard). The list is `lib/forms-hub/registry.ts` — add a form = add one entry. The form itself is ONE shared component, `components/forms/bank-application-form.tsx`, used by both the public link page and the staff preview (`preview` prop: never calls the server, never submits). Admin only: side-menu `adminOnly`, `/forms` in the middleware admin-only list, and the create/list API uses `isSecureAdmin`. A returning user's saved menu order gets `forms` inserted after `storage` (not appended at the bottom).

## How it's built
- **Table** `bofa_intake_requests` (RLS on, no client/anon policy; service role only) and private bucket `bofa-intake-uploads` (10 MiB limit): `scripts/migrations/20261009-2200-bofa-intake-requests.sql`.
- **Pure logic:** `lib/bofa-intake/schema.ts` (fields, document slots, validation — shared by page and server), `lib/bofa-intake/lock.ts` (the one-time rule), `lib/bofa-intake/access.ts` (server gate; the claim is an atomic UPDATE `WHERE status='pending'`), `lib/bofa-intake/url.ts` (link URL from `APP_BASE_URL`).
- **Public page** `app/bank-application/[token]/page.tsx` and **public API** `app/api/bank-application/[token]/` (`route.ts` open/claim, `upload-url/` signed direct-to-storage upload, `submit/`). Deliberately named without "Bank of America" in the URL. Both prefixes are public in `middleware.ts`.
- **Staff (admin only, `isSecureAdmin` — NOT `isAdmin`, whose `user_metadata.role` any logged-in user can set on themselves):** page `app/(dashboard)/bofa-intake/page.tsx` (create link, copy it, list, view answers, 1-hour document downloads, reset, revoke, an amber "Staff email not sent" badge when the notification failed) and API `app/api/bofa-intake-admin/` (kept OUT of the public prefix so the session gate protects it). `/bofa-intake` is in the middleware admin-only list. There is no sidebar entry yet — open it by URL.
- **Tests:** `tests/unit/bofa-intake-lock.test.ts`, `tests/unit/bofa-intake-schema.test.ts`.

## Gotchas, invariants & past bugs
- **Claim only on an explicit Start.** An earlier version claimed on page load; React's dev double-run fired two claims and the page wrongly said "already used", and preview bots could burn links. Now GET never claims; only POST (Start) does. The state fetch is still guarded with a ref (`loaded`).
- **A database hiccup is never "invalid link":** the lookup throws on a DB error and the routes answer 503 / "Something went wrong"; only a truly absent token is 404 "missing".
- **Retries don't pile up files:** the page remembers a finished upload per box and reuses it; signed upload URLs are `upsert: false` so one URL cannot overwrite a stored passport.
- **No IP or browser string is stored on submit** (the columns exist, unused).
- **Strict mode is off in this repo's TypeScript config**, so `if (!x.ok)` does not narrow the result unions here; the routes use `"reason" in gate` / `"error" in result`.
- **Never export a helper from a `route.ts`** (Next route export restriction) — the URL builder lives in `lib/bofa-intake/url.ts`.
- **Submit verifies every file really exists in storage under this link's own token** and only then flips `opened` -> `completed` (so a replay or double-click cannot submit twice).
- **Sandbox email:** the staff notification goes through `gmailPost`, which under `SANDBOX_MODE` captures instead of sending; production sends for real.
- **Local test admin** needs `app_metadata.mfa_exempt = true` or login stops at MFA enrollment.
