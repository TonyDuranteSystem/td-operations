## What it is
The code that turns computed financials into the downloadable **Excel workbook** (P&L + Balance Sheet + detail sheets). There are two builders, and knowing which is authoritative matters:

1. **`lib/tax/financials-excel.ts::buildFinancialsWorkbook`** — renders the Excel **from the tax-financials engine draft** (`buildFinancialDraft` via `getFinancialsView`): P&L totals, per-member M-2 capital roll-forward, and the **prior-return-aware** beginning balances — i.e. the SAME numbers the on-screen review shows. **This is what the tax-financials download route uses** (`app/api/portal/tax-financials/download`). Authoritative. Documented in **tax-returns.md**.

2. **`lib/pnl-generator.ts::generatePnlExcel`** (+ `buildPnlWorkbook`) — the OLDER transaction-based builder. **DELETED 2026-08-19** (card 41f60a18): had been dead since 2026-08-12 (the tax-wizard auto-pipeline scrape and the external tax-form-completed twin were the last callers, removed by the card 4a39e0fd fix wave; attest-handoff, the portal download and the `bank_statement_pnl` MCP tool had already migrated to `buildFinancialsWorkbookForAccount`). `computePnlTotals` and `getIrsRate` are the only exports left in `lib/pnl-generator.ts` now — LIVE (the engine and FX use them).

## Business rules
- **USD only**; P&L amounts at the IRS **yearly-average** rate (`irs_exchange_rates`, `getIrsRate`). Balance-sheet year-end FX (spot vs average) is tracked refinement **R1** — it will improve the draft AND the Excel together.
- `computePnlTotals` (in `pnl-generator.ts`) is the shared signed-totals math (F1 refunds, F3 contributions-as-equity, F4 contra-expense) — pinned by `tests/unit/pnl-totals.test.ts`. Both builders use it (the draft via the engine).

## Gotchas
- **Screen vs file:** always use the draft-based builder (`buildFinancialsWorkbook`) for anything tied to the tax-financials review, so the downloaded file matches the screen. There is no other builder anymore.
- **Don't build a second workbook builder.** Any new "download the P&L" surface should call `buildFinancialsWorkbook`, never a fresh ExcelJS workbook — that duplication (Drive statement-scrape + legacy P&L, removed 2026-08-12) is what produced disagreeing files in the past.
- **Dynamiq's own leftover duplicate rows were cleaned up 2026-08-24** (dev job f6798fda), separately from the 2026-08-12 code fix above that stopped the "cross-parser refs defeat the dedup index" class from happening again. The code fix does NOT retroactively clean data — any account whose statements went through the killed Drive-scrape path *before* 2026-08-12 may still be carrying the same leftover duplicates. Symptom to watch for: a `bank_transactions` unique-index miss where the SAME real transaction exists twice with different `transaction_ref` values (one batch typically `ai-YYYY-MM-DD-N` style, generic description; the other `h-<hash>` style, merchant-enriched description) — or a `bank_name` of literally `'unknown'` whose rows exact-date-and-amount-match an already-correctly-labeled bank. If a client reports a per-bank balance "off by" an amount that's suspiciously close to exactly half their reported total for that bank, that's the tell (Relay's case: the stored net was exactly 2× the client's reported gap). No sweep of other accounts has been done yet — this is a known-possible gap, not a confirmed one elsewhere.
